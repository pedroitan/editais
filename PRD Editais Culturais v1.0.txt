## 🎯 VISÃO ESTRATÉGICA

### O Problema Real

**Artistas/Criadores:** Difícil encontrar editais culturais relevantes  
**Produtoras:** Perdem prazos importantes por falta de centralização  
**Instituições:** Editais espalhados em múltiplos sites (Funarte, MinC, SECULT, etc.)

### Nossa Solução

Ecossistema que:
1. Centraliza editais culturais de múltiplas fontes
2. Alerta sobre prazos próximos
3. Filtra por área (música, teatro, dança, artes visuais)
4. Facilita inscrição com links diretos

### Diferencial Competitivo

> Sites de editais existem, mas são manuais e desatualizados.  
> **Nós automatizamos scraping + alertas inteligentes.**

## 🛠️ STACK TÉCNICA

### Core
- **Scrapers:** Python (BeautifulSoup + Scrapy) ou Node.js (Playwright)
- **Database:** Supabase (PostgreSQL)
- **Frontend:** Next.js 14 + React Server Components
- **Styling:** Tailwind + shadcn/ui
- **Deploy:** Vercel (frontend) + GitHub Actions (scrapers)

### Scraping
- **Funarte:** BeautifulSoup (HTML estático)
- **MinC:** Playwright (pode ter JS)
- **SECULT-BA:** BeautifulSoup ou Scrapy
- **Lei de Incentivo:** BeautifulSoup

### Alertas
- **Email:** Resend (gratuito) ou SendGrid
- **Job:** GitHub Actions scheduled workflow
- **Rate Limiting:** 1 email/dia por usuário

- Editais ativos: 50+ (Mês 1) → 200+ (Mês 6)

## 🚨 RISCOS E MITIGAÇÕES

| Risco | Mitigação |
|-------|-----------|
| Sites mudam layout frequentemente | Scrapers robustos com seletores flexíveis |
| Editais duplicados entre fontes | Deduplicação por título + instituição |
| Prazos mal formatados | Parser de datas robusto + fallback manual |
| Taxa de entrega de emails baixa | Usar serviço confiável (Resend/SendGrid) |
| Scrapers bloqueados por rate limiting | User-Agent rotation, proxies se necessário |
